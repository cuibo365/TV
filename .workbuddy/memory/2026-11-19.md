## 5.4.1 播放机制考证（15:30 前后）
- 播放失败三级切换链：PlayerManager 重试≤2次(解码错误硬软解互换/IO错误retryFormat重探格式) → VideoActivity.startFlow 换解析(checkParse)→换线路(checkFlag)→全网搜片换站点(nextSite)；前提 Site.isChangeable()==1
- changeable 三态：JSON sites[].changeable，null/1=允许,2=UI关闭,0=锁定(UI不可改)；TV端开关藏在 设置→点播首页 站点弹窗顶部第2个按钮(换源模式)，单击/长按切换
- 解析(parses)：JSON parses 数组 + 内置 Parse.god()(type4并发) 自动插到列表头；type 0=WebView嗅探 1=json 2/3=json扩展 4=superparse并发
- 无 parses 配置时 shouldUseParse() 短路 false，直接跳过解析级，失败走 checkFlag→nextSite；仅站点自声明 jx=1/parse=1 仍会跑 ParseJob

## xiaoya 站报错根治（17:35-17:58）
- **根因链**：FongMi 壳的 console.log 本身就是坏的——quickjs-wrapper（wang.harlon 3.2.3）的 console polyfill（编译在 libquickjs-android-wrapper.so）① print 调 globalThis.format(value)（壳从未定义）；② `globalThis.log = console.log` 裸赋值后调 log(...) 时 this≠console，this.print 变 undefined。两处都抛 QuickJSException: not a function at console.js:242。
- **壳注册给 JS 的原生函数没有任何 log 类**（仅 s2t/t2s/getPort/getProxy/js2Proxy/setTimeout/_http/req/joinUrl/md5X/aesX/rsaX），console.*→Logger(tag=TV-quickjs) 是唯一 JS 日志通道。
- **修复（兼容增量，pc-box 有自带 log 整块跳过）**：垫片改为
  ```js
  if (typeof log === 'undefined') {
      if (typeof globalThis.format === 'undefined')
          globalThis.format = (v) => typeof v === 'string' ? v : JSON.stringify(v);
      globalThis.log = (...args) => console.log(...args);  // 箭头转发保 this
  }
  ```
  应用到 lib/alist/drive.js、lib/alist/index.js、alist_xiaoya.js（quark.js 无 log 垫片不受影响）。
- **验证**：设备日志 [alist] 登录就绪：丫仙女（已带 token）、init ok drives=1 index=video，目录浏览正常。「登录失败」报错是假的——登录一直成功，是响应解析后的 log 调用炸断流程。debug 日志（打印 token）已撤。
- ADB 经验：沙箱里 adb daemon 每条命令间退出，connect+push+shell 必须同一条命令链；Git Bash 把 /sdcard/... 转本地路径，push 要 MSYS_NO_PATHCONV=1 且本地路径用 D:/ 形式。

## v1 签名补齐（21:15）
- 现象：蜂蜜官方5.5.6 在小米电视上手动安装报「解析程序包异常」，OK5.1.6 正常。根因非安卓版本：5.5.6 是 v2-only 签名（minSdk24 时 AGP 默认关 v1），部分电视端安装器老解析路径认不出 v2-only 包；OK5.1.6 v1+v2 双签所以能装。
- 我们自己的包同样是 v2-only。修复：
  1. 用 JetBrains JDK21（~/.gradle/jdks/，PATH 里 JDK8 读不了 PKCS12 keystore）+ apksigner 对两个 debug APK 补签 v1+v2，已替换原文件。
  2. app/build.gradle 固化：signingConfigs.debug enableV1Signing=true，buildTypes.debug 引用之——以后重新打包含 v1。
- 验证：apksigner verify --min-sdk-version 23 → v1 true / v2 true；META-INF/ANDROIDD.SF+RSA 在包内。
- 注意：apksigner verify 默认按包 minSdk(24) 判定，v1 会显示 false，需 --min-sdk-version 23 才显示 true。
